An **MCP (Model Context Protocol) server** that exposes the REST APIs of
**Proxmox VE** and **Proxmox Backup Server (PBS)** as a set of callable tools
for LLM agents, IDEs, and assistants.

Inspect and operate a Proxmox virtualization cluster and its backup server from
any MCP client: **PVE nodes, QEMU VMs, LXC containers, storage, network,
cluster/status, and tasks/logs**, plus **PBS datastores, backups/snapshots,
notes, verify, and prune** — all through a clean, typed tool interface. Both
backends are **optional**: each is enabled only when you supply an endpoint and
an API token for it.

- **Proxmox VE**: `https://pve.example.com:8006`, API path prefix `/api2/json`
- **Proxmox Backup Server**: `https://pbs.example.com:8007`, API path prefix `/api2/json`
- Language / runtime: **Go 1.27.1**
- MCP SDK: `github.com/modelcontextprotocol/go-sdk v1.8.0`
- Logging: logrus (text or JSON), including the SDK's internal logs via a `slog → logrus` adapter
- License: **Apache-2.0** — © 2026 Igor Shishkin

## Features

- **Two optional backends + system tools — 46 MCP tools in total:**
  - **Proxmox VE** (`pve_*`, 31 tools): nodes & cluster (list/status/resources/next-id),
    QEMU VMs (list/get/status/create/start/stop/reboot/shutdown/migrate/delete), LXC
    containers (list/get/status/create/start/stop/reboot/shutdown/delete), storage
    (list/status), network (list), tasks (list/status/log), and PVE version.
  - **Proxmox Backup Server** (`pbs_*`, 13 tools): datastores (list/status),
    backups/snapshots (list/get/restore/forget), notes (get/set), verify (start/status),
    prune (start/status), and PBS version.
  - **System**: `ping`, `status` — always registered; report which backends are enabled.
- **Backends enabled only when configured:** a backend whose `endpoint` or `token`
  is missing is simply **absent** — its tools are not registered and nothing fails.
- **API-token authentication** (`Authorization: PVEAPIToken=user@realm!tokenid=uuid`),
  read once per backend from config — **never per-call, never logged**.
- **Local stdio mode** today; the transport and `TokenSource` boundaries are designed
  so a future **remote (Streamable HTTP) + OAuth2** mode can be added without
  rearchitecting.
- **Clean Architecture / DDD** with no `internal` package; the core has zero
  dependencies on the MCP SDK, HTTP, logrus, or any Proxmox client.
- **Read vs write discipline:** idempotent reads are retried; mutations are never retried.
- **TLS verification is always on** — self-signed/custom CAs supported only via a
  `ca_cert_path` per backend (no `insecure_skip_verify` switch).

## Configuration

Configuration is read from **environment variables** (via
[`kelseyhightower/envconfig`](https://github.com/kelseyhightower/envconfig)) —
there is **no YAML/config file**. A backend is **enabled only if both its
`endpoint` and `token` are present**; if either is empty, the backend is
disabled and its tools are not registered.

| Variable | Description |
|---|---|
| `PVE_ENDPOINT` | PVE API endpoint (e.g. `https://pve.example.com:8006`). Non-empty enables the PVE backend. |
| `PVE_TOKEN` | PVE API token (`user@realm!tokenid=uuid`). Non-empty enables the PVE backend. |
| `PVE_CA_CERT_PATH` | Optional custom CA (PEM) for the PVE endpoint. Empty = system roots. |
| `PBS_ENDPOINT` | PBS API endpoint (e.g. `https://pbs.example.com:8007`). Non-empty enables the PBS backend. |
| `PBS_TOKEN` | PBS API token (`user@pbs!tokenid=uuid`). Non-empty enables the PBS backend. |
| `PBS_CA_CERT_PATH` | Optional custom CA (PEM) for the PBS endpoint. Empty = system roots. |
| `LOG_LEVEL` | Log level (`trace`, `debug`, `info`, `warn`, `error`). **When set, logging is enabled**; when unset, logging is **disabled** (no logs are emitted anywhere). |
| `LOG_FILENAME` | Path of the log file used when `LOG_LEVEL` is set (default `/tmp/mcp-proxmox.log`, mode `0600`). |
| `LOG_FORMAT` | Log format: `text` (default) or `json`. |
| `ENABLE_MUTATIONS` | Register mutation tools (default `false`). When `true`, mutation tools (`pve_vm_create`, `pve_vm_resize`, `pve_vm_migrate`, `pve_ha_add`, `pve_vm_backup`, `pbs_verify_start`, `pbs_gc_start`, `pbs_prune_start`, `pbs_sync_start`) are registered for enabled backends; when `false`, only read-only query tools are exposed. |

These are the **only** environment variables the server reads. Proxmox API
tokens are long-lived, privilege-scoped credentials configured once per backend
and re-used on every call — **never per-call, never logged**. TLS verification
is **always on**; a self-signed/custom CA is supported only via the per-backend
`*_CA_CERT_PATH` variable.

### Logging

Logging is handled by [logrus](https://github.com/sirupsen/logrus) and is
**disabled by default**: unless `LOG_LEVEL` is set, no logs are emitted at all
(a stdio server must not pollute the protocol channel). When `LOG_LEVEL` is set,
logs are written to `LOG_FILENAME` (default `/tmp/mcp-proxmox.log`) at that
level and in `LOG_FORMAT` (text or JSON). When enabled, the **very first** log
line is the startup banner:
`Starting mcp-proxmox/<version> (commit: <commit>; built at <ts>) ...`.

Use `LOG_LEVEL=trace` or `LOG_LEVEL=debug` for request-level diagnostics
(`trace` logs method + URL path only). **API tokens and `ca_cert_path` content
are never logged** — at most the header *name* may appear at trace level. Tool
arguments that look sensitive (token/password/secret/…) are redacted in logs.

Because the server runs over stdio (clients launch it as a subprocess and don't
capture stderr), setting `LOG_LEVEL` writes the log to a file you can tail:

```sh
export LOG_LEVEL=debug
# optional: export LOG_FILENAME=/var/log/mcp-proxmox.log
# optional: export LOG_FORMAT=json
tail -f /tmp/mcp-proxmox.log
```

## Running

Set the API token(s) as environment variables, then start the server:

```sh
export PVE_ENDPOINT="https://pve.example.com:8006"
export PVE_TOKEN="user@pam!tokenid=abc123=deadbeef"
export PBS_ENDPOINT="https://pbs.example.com:8007"
export PBS_TOKEN="user@pbs!tokenid=xyz789=deadbeef"

./bin/mcp-proxmox   # logging off by default; enable via LOG_LEVEL env
```

The server speaks the MCP protocol over **stdin/stdout**. Launch it from your MCP
client as a subprocess (see the client configuration below).

## Tool domains and examples

| Prefix | Domain | Example tools |
|---|---|---|
| `pve_` | Proxmox VE | `pve_node_list`, `pve_vm_start`, `pve_lxc_create`, `pve_storage_list`, `pve_network_list`, `pve_task_status`, `pve_version` |
| `pbs_` | Proxmox Backup Server | `pbs_datastore_list`, `pbs_backup_list`, `pbs_backup_restore`, `pbs_backup_notes_get`, `pbs_verify_start`, `pbs_prune_status` |
| — | System | `ping`, `status` |

> **Enablement recap:** all `pve_*` tools are registered only when the PVE backend
> is configured; all `pbs_*` tools only when PBS is configured. `ping`/`status`
> are always registered and report which backends are active.

> **Restore/forget semantics (PBS):** `pbs_backup_restore` restores a snapshot and
> returns the resulting task UPID; `pbs_backup_forget` removes a snapshot from the
> datastore catalog. Both are mutations and are **never retried**.

> **Read vs write:** `query` tools (reads/`GET`) are idempotent and retried;
> `mutation` tools (writes/`POST`/`PUT`/`DELETE`) are **never retried** to avoid
> repeating a write.

## Docker

The [`Dockerfile`](./Dockerfile) produces a minimal `FROM scratch` runtime image
that carries only the static binary plus the CA certificate bundle (needed for
TLS to the Proxmox APIs). **The image build is isolated — it does not compile the
binary.** Build the binary first with goreleaser (artifacts land in `dist/`), then
build the image, which only COPYs the ready artifact.

> This server is a **Local (stdio)** MCP server, so the container image is a
> **local convenience only** — it is **not** built or published by any CI/CD
> pipeline (there is no `container-image` job or registry push). It lets you run
> the stdio binary in an isolated runtime (e.g. `docker run` with env vars) for

## CI/CD

A single **GitHub Actions** pipeline (`.github/workflows/ci.yml`) runs the quality
gates **lint → arch → test (`-race`) → cover (95% gate) → mutation → build → sec →
govulncheck** on every push and pull request:

- **`lint`** — `make lint` (golangci-lint + vet + gofmt + go-arch-lint + gosec +
  govulncheck).
- **`test`** — `make test` (`go test -race` + a **hard 95% `cover-core` gate**; the
  build fails below it).
- **`mutation`** — `make mutation` (gremlins 80/80) as a **hard gate** (fails on
  surviving mutants).
- **`secrets`** — `make secrets` (gitleaks over the **full git history**) as a
  **hard gate**.
- **`build`** — `make build` (goreleaser snapshot into `dist/`).

A separate **release workflow** (`.github/workflows/release.yml`) runs
[goreleaser](https://goreleaser.com) on every git tag `v*` and publishes the
cross-compiled binaries/archives to the **GitHub Release** (waiting for CI to
pass first). The container image is **not** built or published by CI (see
[Docker](#docker)).
